# FCI — agent guide

**Foundations of Computational Interaction (FCI)** is a research program for formally describing,
measuring, modeling, and predicting human–computer interaction. It is a **research program, not an
established discipline**; its scientific necessity and empirical advantage remain to be demonstrated.

> **Research doctrine lives in [`.agents/AGENTS.md`](.agents/AGENTS.md)** — the guiding principle, the
> three architectural layers, the epistemological questions, editorial language rules, example-identity
> rules, and publication quality gates. Read it before touching the corpus.
>
> **This file is the operational layer**: layout, gates, versioning, and working conventions.

## Naming canon

- **FCI** is the preferred short name. Avoid institutional phrasing ("the discipline of…").
- **`CIS-EX-NNN` example identifiers are never renamed or renumbered.** Identity stability is a
  contract: a material semantic change gets a *new* identifier; a correction that restores the
  documented contract keeps the existing one and updates its validation record.
- The `cis_` C namespace is retained under the legacy policy in [`app/NAMING.md`](app/NAMING.md).
  Residual `cis` symbols are deliberate, not oversights.

## Verification gate

Run before proposing a merge. CI runs the same commands.

```bash
cd app && make test                      # build + unit, stress, example, schema, benchmark suites
python3 scripts/check-doc-links.py       # every internal markdown link resolves
python3 scripts/check-structure.py       # documented directories actually exist
```

### CI gates

| Workflow | What it enforces |
|---|---|
| `ci.yml` | Builds and tests the substrate under **both gcc and clang**, then asserts the `make conformance` vectors are **byte-identical across compilers**. Plus corpus link and structure integrity. |
| `pr-checks.yml` | Per-layer record-keeping; flags multi-layer version bumps that never mention coupling. |

**`conclusion` / `conclusion-pr` are the required checks**, not the individual jobs. They assert every
dependency *succeeded* — a skipped or cancelled job can never count as green. Making an individual job
required instead would let a docs-only PR pass by skipping everything.

**Why both compilers.** The substrate claims freestanding C11 determinism. Two builds each passing
their own tests does not test that claim; comparing their conformance vectors does.

## Versioning — layers move independently

FCI versions theory, schemas, software, publication infrastructure, and examples **independently**.
A shared number never implies cross-layer conformance. The policy is
[`app/VERSIONING.md`](app/VERSIONING.md) and it is **load-bearing, not decorative**:

- a theory patch does not require a software release;
- a schema release does not imply empirical validation;
- passing C tests establishes reference-kernel conformance **only**;
- cross-layer compatibility must be **declared in a conformance record** — never inferred from equal
  version numbers.

**Changelogs are per layer, for the same reason.** A single repo-wide changelog would assert exactly
the coupling the policy denies.

| Layer | Record |
|---|---|
| Corpus (`docs/`) | [`docs/CHANGELOG.md`](docs/CHANGELOG.md) |
| Substrate (`app/`) | [`app/RELEASE_NOTES.md`](app/RELEASE_NOTES.md) |

CI reads the **diff** of these files, not merely whether they exist — an untouched changelog is the
failure it catches.

## Working conventions

- **Status honesty.** Never describe something as established unless a record confirms it. Distinguish
  *documented*, *implemented*, *tested*, and *empirically validated* — they are four different claims.
  When in doubt, state the weaker one.
- **Branch naming.** Named for the work: `feat/…`, `fix/…`, `docs/…`, `chore/…`, `research/…`. Never
  tool-generated or session-identifier names — branch names are permanent in PR records.
- **Git voice.** Normal human engineering prose. **No** `Co-Authored-By`, no AI-attribution trailers,
  no "generated by" footers, and no agent/assistant references in anything tracked — code, docs,
  commits, or PRs.
- **Don't commit or push unless asked**, except on a feature branch.
- **Verify the finish line.** "CI armed" ≠ green; "PR approved" ≠ merged. Check the actual state
  (`gh pr view <n> --json state`) before reporting completion.

## Research practices

The empirical protocol this program holds itself to — preregistration, the discovery criterion,
negative results, and evidence provenance — is documented in
[`docs/90_Project/Research_Practices.md`](docs/90_Project/Research_Practices.md).

The short version, because it governs how anything here may be *claimed*:

- A claim's **maturity** (how settled) and its **provenance** (what backs it) are separate dimensions.
  A fixture written against the implementation it was designed alongside cannot falsify that design.
- **Negative results are permanent.** A hypothesis that was held and disproven is recorded, not
  deleted — the abandoned intuition is the thing most likely to be re-proposed later.
- **Predictions are registered before the work**, and falsifications keep the lesson they taught.
  Accuracy is expected to *fall* as scope widens; a rising accuracy with widening scope means the
  predictions are being written to be safe.

## Engineering craft (hard-won — keep these)

- **A documented claim that was only ever verified one way is an untested claim.** The substrate's
  README asserted `make test` "rejects any undefined external symbol." True under GCC; false under
  Clang, which emits `memcpy` for struct assignment. Both conform — C11 §4 permits a freestanding
  implementation to require `memcpy`/`memset`/`memmove`/`memcmp`. The invariant is now stated
  precisely and tested in both directions (a real external dependency is still rejected).
- **Fix the diagnostic before the defect.** The first cross-compiler failure printed only
  `Error 1` — undiagnosable. Making the check *report the offending symbol* came first; guessing
  would have led to a plausible wrong fix that hid the real question.
- **Prose drifts where links do not.** `docs/README.md` described two directories that did not exist
  and omitted three that did, and the link checker passed the whole time — it validates links, not
  claims about structure. `scripts/check-structure.py` closes that specific gap; assume other prose
  claims are unverified until something checks them.
- **A gate that cannot fail is not a gate.** After changing a check, prove it still rejects the thing
  it exists to catch.

6. **Adding an executable example** → allocate the next `CIS-EX-NNN`; see `.agents/AGENTS.md` §6.2.
7. Always close with the verification gate above, and record the change in the **layer's own** log.
